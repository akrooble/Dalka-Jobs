## Navigation and shared interactions

Reuse the existing panel shell, brand tokens, local fonts, fields, dialogs, tables, pagination, feedback and version-conflict patterns. Super-admin navigation groups: overview; companies/jobs/lists (reuse current live screens); people/assignments; trust/authority/reports/content; recruitment/sharing; billing/prices/payments; settings/activity. Recruiter navigation: assigned jobs, candidates, interviews, own permitted notes. Company navigation: own jobs, candidate main list, rejected view, progress. Company navigation has no create/edit/stage/share/payment controls. Finance remains a super-admin area, not a new finance role.

Desktop 1440: persistent sidebar, title/breadcrumb, primary action beside title, filter toolbar, bounded table and optional detail pane. Tablet 768: collapsible labelled navigation, one-column detail/forms, table scroll confined to its labelled region; action labels remain visible and reachable. Do not hide warnings/permission feedback on narrower screens. Later phone checks 375 must keep shell/links usable although management is desktop/tablet first. Maintain skip link, semantic headings, label/error associations, visible focus, dialog focus trap/return and keyboard-accessible menus. No essential hover-only action. Reuse current early CRUD instead of introducing parallel company/job/list editors.

Every screen begins with server session/access verification. Loading has no stale private rows from a previous role. Genuine empty result supplies a permitted next action; error supplies retry without claiming empty. Forbidden/revoked state clears private rows/dialog data, cancels obsolete loads and links to sign-in or authorized start. Never show a sample dataset after a live failure. Unsaved edits survive validation/service errors in memory only; stale-version conflict offers reload/review, never silent overwrite. Logout/permission revocation clears private drafts. Buttons guard duplicate submits; backend idempotency/versions enforce correctness. Success feedback appears only after server commit and reflects reloadable state.

## Key screen flows

Users/assignments: directory → selected user/job → permitted assignment form → versioned confirmation → refreshed list. Revoking an assignment must invalidate subsequent direct candidate/CV requests, not merely hide a row. Role changes require explicit session-revocation and last-super-admin decisions; until approved show policy gate rather than an operational button. MFA status may be displayed, enrollment secret never is.

Trust/authority: checklist and authority appear as separate labelled sections. Authority review shows approved scope and validity, with missing/expired/revoked states. Publication eligibility comes from the server; frontend cannot turn on recruitment with a badge or bypass. Reports distinguish unreviewed/reviewed status only after workflow approval; do not invent removal powers. Content edits show current and draft version; exact policy text needs owner approval before publishing.

Recruitment: select job → paginated permitted candidates → permitted candidate projection → timeline/interview/notes tabs. Notes private by default; no sharing checkbox until sharing authority and recipient projection approved. Proposed stage transitions are in contract choice G, not implemented defaults. Interview form uses Africa/Mogadishu display with explicit timezone/instant; schedule/reschedule/cancel records distinct history rather than silently overwriting a previous invitation. Rejecting a candidate removes it from company main view, never automatically grants the rejected view a CV.

Explicit sharing: candidate → choose eligible own job-company recipient and exact permitted fields → confirmation summary → server grant → versioned status. Revocation rechecks every future read/download and clears open company view on refresh/revalidation. Previously downloaded bytes cannot be recalled; UI must not promise recall. Sharing survival after rejection, whether a shared note is allowed and retention/deletion behavior remain policy gates; default withheld in prototypes until approval. No CV redaction feature.

Company: jobs → job progress → eligible main list → candidate summary. Submitted may contribute only to an approved aggregate projection; no submitted identity/detail is exposed. Rejected view explains unavailable policy until its DTO is approved. Shared contact/CV action is visible only with server grant, but hidden buttons never substitute for server checks. Foreign job/candidate/file IDs return a consistent denied/missing result without existence leak.

Finance: draft editor → review → issue action → locked Sent detail. **Proposed for owner review:** allocate the unique `DJ-YYYY-0001` sequence under lock at issue time, never reuse it; allocation/reset timing is not yet approved. Draft content remains editable; Sent financial/content changes require cancel/reissue. Status/payment recording remains allowed only by approved ledger rules. Overdue derived from due date and unpaid balance; manual tax line only. Partial payment records distinct immutable ledger entries; validate amount/currency/date/idempotency. Exact rounding/overpayment/refund/cancellation and numbering reset/allocation timing remain undecided. No unpaid-invoice publication gate. PDF contains company/job billing information only and is downloadable for manual sending. Summaries never sum USD with another currency.

Overview/activity/settings: each count links to the corresponding scoped queue and supplies its time basis; no speculative conversion/engagement analytics. Activity records only allowed IDs/times and uses approved display mappings; do not duplicate deleted profile or note contents into a durable log. Secret settings remain outside ordinary UI, and production phone sign-in cannot be enabled by a settings toggle.
