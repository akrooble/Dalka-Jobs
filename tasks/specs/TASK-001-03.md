## Implementation approach / credential handling
1. User runs setup-local.ps1 from repository root. It requires running postgresql-x64-18 and queries Windows TCP listeners on5433. Every bound address must be127.0.0.1 or::1; wildcard/non-loopback addresses fail before prompt/mutation. It neither starts/stops the service nor edits configuration.
2. Prompt Read-Host -AsSecureString for postgres superuser password. Build the helper before prompting, then convert only inside try/finally for an anonymous child-stdin JSON pipe into the directly launched helper executable (never go run, which obscures exit codes). Never place admin secret in .env, temp file, argv, environment or output. Clear references/free SecureString buffer after sending; managed-runtime copies exist in process memory only and cannot be promised deterministic erasure. No transcription of the plaintext prompt value; never print serialized request or arbitrary child errors.
3. Helper hard-codes127.0.0.1:5433/postgres/postgres, ignores inherited connection choices, sets short timeouts and validates server_version_num=180006, port5433, loopback server endpoint, and listen_addresses limited to localhost/127.0.0.1/::1. No arbitrary DNS hostnames accepted. Require postgres superuser, SCRAM password encryption and valid host authentication rules all using scram-sha-256; unsafe/unreadable rules fail closed without editing them. This intentionally conservative check may reject unrelated host authentication rules; owner must review their service configuration independently.
4. Advisory lock serializes this setup; before mutation refuse if .env, dalka_dev, dalka_jobs_dev or dalka_jobs_check already exists. No auto-adoption, overwrite, password rotation, drop or cleanup. Fixed identifiers only. Role is LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS, no inherited memberships.
5. Generate32 random bytes encoded as64 hex characters. Create .env exclusively as an empty file; remove inherited Windows ACLs and grant current user access before writing app password. On ACL failure no secret is written; no automatic deletion. .env is the sole on-disk app-password location. Database receives a SCRAM verifier generated with standard Go crypto, not cleartext app password. No admin credential is written into SQL.
6. Write/sync .env before provisioning so a partial failure cannot lose a created role's password. Create role, two databases owned by dalka_dev with ALLOW_CONNECTIONS false; REVOKE CONNECT FROM PUBLIC on those two databases and explicit GRANT CONNECT to dalka_dev, then enable connections only after ACL success. Interruption before this leaves the new database closed. No grants/config changes on other databases. Database creation is nontransactional; partial failure leaves local .env and possibly role/one database. Refuse rerun; user inspects locally, no destructive rollback. PostgreSQL service/configuration remains unchanged throughout.
7. check-db.ps1/dbcheck parse only expected .env keys, require exact role/host/port/database names and hex password, never evaluate dotenv text. Connect only as dalka_dev to both databases. Check18.6, loopback settings, SELECT1, role privilege/membership constraints, database ownership and absence of PUBLIC CONNECT. Never request superuser credentials; no table/schema/product data modifications.
