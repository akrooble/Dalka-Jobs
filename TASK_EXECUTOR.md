# Task execution

Follow [AGENTS.md](AGENTS.md) and implement only an approved specification from `tasks/specs/`.

1. Read the specification and approval evidence.
2. Verify current Git state and applicable instructions; preserve existing work.
3. Confirm affected files, dependencies, and architecture against repository evidence.
4. Write a short implementation plan in the task execution log.
5. Implement one small logical change at a time within approved scope.
6. Add or update meaningful tests proportionate to behavior and risk.
7. Run targeted tests, then relevant lint/type checks using evidenced commands and working directories.
8. Inspect the final diff and untracked files; update relevant documentation.
9. Log changed files, commands, exit results, deviations, blocked prerequisites, and remaining lifecycle phases.
10. Report actual results and submit for independent review.

Stop and report architectural conflicts or serious security risks. Never hide failures, claim unexecuted checks passed, or introduce unrelated changes. No application verification commands currently exist; establish them through approved implementation rather than inventing successful checks. Keep release phases pending until separately authorized.
